# PHILEON — Product Requirements Document

## Original Problem Statement
High-end luxury jewelry e-commerce site (PHILEON) with strict cinematic editorial UI (LA BÊTE visual language). Ongoing: content/UI expansion of Fine Jewelry, Inspiration Vault, and now Bracelets, with cinematic vertical galleries, autoplay-muted-loop hero video, and product-page detail pages per SKU.

## Product Registry (implemented)
- **Fine Jewelry Rings**: Rhythm Mesh, OVATION Ribbed Ring, BAJAN JOE Signet Ring, **QUADRIGA DOMINUS (NEW)**, RHYTHM MESH, LA BÊTE, CYPHER, BOUND, APEX, HOMAGE, TRIBUTE: LA BÊTE, BLESSED, COOGI I, TOLA II, Galatians 6:14, TRACE, IL MORSO DEL RE

- **Inspiration Vault**: Orbit Lumière, Viridian Teardrops, Prismatic Laurel, Noir Tide, Prima Wave, Noir Cadence, Liaison, STAMPEDE, NIGHTFANG, PARALLAX
- **Other**: PTP Cuff, Forme Cuff, Désir Corset, Rosaria, Alejandra Heels, La Marva, Annie Rose, Monika Couture, Katrina Cascata

## Architecture
- Frontend: React (CRA) — pages under `/app/frontend/src/pages`, product data in `/app/frontend/src/data/products.js`
- Backend: FastAPI (routes `/api/*`), MongoDB via `MONGO_URL`, Stripe checkout scaffolding in `/app/backend/routes/checkout.py`
- Shared components: `RingProductPage`, `RingSizeSelector`, **`WristSizeSelector` (NEW)**, **`BraceletSizeGuideModal` (NEW)**
- Custom IntersectionObserver lazy-loading + quadruple-redundant video loop (do not refactor)

  - **SEC-001 · Unauthenticated catalog / inventory / upload mutation (HIGH)** — Root cause: `routes/products.py` mutating endpoints had no auth dependency and were mounted at `/api`. Fix: every mutating route (`POST /api/products`, `PUT /api/products/{id}`, `DELETE /api/products/{id}`, `PUT /api/products/{id}/inventory`, `POST /api/products/upload-image`, `POST /api/products/upload-video`) now uses `Depends(verify_admin)` via a safe intra-module import from `server`. Verified: unauth on all 6 → 403; authed → 200/expected. Read-only `GET /api/products` still 200 (public listing preserved).
  - **SEC-002 · Stored XSS via unauthenticated upload served with attacker MIME (HIGH)** — Root cause: `routes/products.py:186` stored the client-supplied `content_type` verbatim and `server.py:1029-1038` streamed it back through `/api/files` with no `X-Content-Type-Options`. Fix: (a) uploads validated by real magic bytes (JPEG `FF D8 FF`, PNG `89 50 4E 47 0D 0A 1A 0A`, WebP `RIFF….WEBP`, MP4 `ftyp`, WebM `1A 45 DF A3`) — HTML disguised as image now rejected 415 even for an authenticated admin; (b) stored content-type is server-derived from bytes, never from the client; (c) new `_safe_stream_headers` on both `/api/files/*` and `/api/admin/concierge/attachments/*` enforces an allowlist of inline types (`image/jpeg|png|webp|gif`, `video/mp4|webm|quicktime`) — anything else is forced to `application/octet-stream` + `Content-Disposition: attachment`; (d) `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cache-Control: private, max-age=300` on every streamed response. Verified live: authed upload of a `.html` renamed to `.jpg` → 415; real JPEG → 200 and served with `content-type: image/jpeg` + all hardening headers.
  - **SEC-003 · Hard-coded, source-committed customer JWT secret (HIGH)** — Root cause: `services/auth.py:13` had `SECRET_KEY = "phileon-customer-jwt-secret-key-change-in-production"` — anyone with the repo could forge customer tokens. Fix: `SECRET_KEY = (os.environ["CUSTOMER_JWT_SECRET"] or "").strip()`; startup fails closed with a `RuntimeError` if the env var is empty; a fresh 64-char `token_urlsafe(48)` was generated into the untracked `/app/backend/.env` (value never printed). Verified: a JWT forged with the old hard-coded secret returns **401 Invalid token** at `/api/auth/me`; a JWT signed with the new env secret verifies signature (returns 401 only when the `sub` UUID doesn't correspond to a real customer, as expected). Rotation of the env value instantly invalidates every previously issued customer token.
  - **SEC-004 · Unescaped user input in internal Concierge notification email (MEDIUM)** — Root cause: `server.py:1636-1651` interpolated raw `message`, `name`, `email`, `summary`, `reference`, and `product.name` into the internal notification HTML. Fix: `html.escape` applied to every user-controlled string before templating on both the customer acknowledgment and the internal alert; plain-text body left as text (fine for text/plain). Verified via unit-replay: `<script>alert(1)</script>` and `<img src=x onerror=alert(1)>` render as escaped entities in both templates; product-name `DRAPE <b>bogus</b>` renders as `DRAPE &lt;b&gt;bogus&lt;/b&gt;`.

    - New ASGI `SecurityHeadersMiddleware` — every response now carries `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: interest-cohort=(), browsing-topics=()`, and `Strict-Transport-Security: max-age=31536000; includeSubDomains`.
